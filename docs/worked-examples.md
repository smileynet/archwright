# Worked Examples

Mappings from Alexander's patterns to games/applications, showing how the force-resolution language applies.

## #127 Intimacy Gradient

**Alexander:** public→private sequence in buildings.

**Games/apps:** onboarding / progressive disclosure.

| Field | Content |
|-------|---------|
| Desire | Players feel oriented before exposed to depth |
| Constraint (hard) | Attention budget |
| Tension | Depth wants to be shown; comprehension wants it hidden |
| Resolution | Stage exposure shallow→deep |
| Hands-down | A progression state machine + gated data unlocks |

## #159 Light on Two Sides

**Alexander:** Every room lit from two directions for depth perception and comfort.

**Games/apps:** Critical state legible from two independent feedback channels. A player should never rely on a single indicator for important information.

## #106 Positive Outdoor Space

**Alexander:** Outdoor spaces shaped as positive figures, not leftover gaps between buildings.

**Games/apps:** Negative space / whitespace as intentional, not leftover. Empty screen areas and quiet moments are *designed*, not merely "where we haven't put UI yet."

## #112 Entrance Transition

**Alexander:** The threshold between street and building creates a psychological shift.

**Games/apps:** The first-run threshold. The experience of crossing from "not in the app" to "in the app" is a designed moment — loading screens, title sequences, tutorials as ritual passage.

## #253 Things From Your Life

**Alexander:** A building should contain objects made by the inhabitants themselves.

**Games/apps:** Player customization / expression. The system provides space for player-authored content — cosmetics, base building, user-generated levels — making it *theirs*.

## Using These Examples

Each mapping demonstrates:
1. Identify the original forces (what Alexander was resolving)
2. Translate the forces to the new domain (games/apps) — same tension, different vocabulary
3. Find the resolution that works in the new medium
4. Trace hands-down to architectural commitments (state machines, data models, UI patterns)

The worked examples are candidates for [Spike S1](../.memory/research-plan.md) — validating the pattern schema against concrete instances.
